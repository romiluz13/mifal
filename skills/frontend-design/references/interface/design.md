# Design and UX

Read for the affected surface; scale the work to the task. This is the primary
Matt interface guidance, adapted from reviewed Impeccable 4.8.0 material.

## Ground the direction

The accepted brief, real product facts and repository design system are the
authority. Read existing requirements/context directly; reuse the current task
record. A missing DESIGN.md does not erase an established interface. A
refinement preserves identity and behavior; a redesign changes the agreed
visual scope while preserving factual content and user tasks.

Identify the surface's purpose:

- **Decide and act:** marketing/pricing; make the value, evidence and primary
  action clear, with one memorable visual idea when useful.
- **Complete a task:** forms, dashboards, settings and tools; familiar controls,
  consistent states, scanability and efficient completion lead.
- **Understand:** documentation/help; hierarchy, reading measure and navigation.
- **Experience an artifact:** galleries/portfolios; let the work lead.

A product's marketing page and dashboard can have different purposes. Brand
expression must fit the current surface rather than replacing its task. Scale
ambition to the purpose: decide-and-act and artifact surfaces get a committed
point of view; on task and reading surfaces ambition shows as precision and
restraint, and patterns people already know earn their place.

## Define UX before decoration

Record the person, starting state, task, success and affected flow in the
existing plan. Resolve information hierarchy, navigation, meaningful labels
and the next action. For affected controls, cover realistic content ranges,
loading, empty, success, error, disabled and permission states.

Plan recovery: preserve useful input, explain the specific problem, give a
next action, and handle back/cancel or repeated submission where relevant.
Avoid inventing capabilities, claims or testimonials. An assumption about
what users understand remains an assumption until user validation.

## Compose deliberately

Derive type, palette, spacing, imagery and layout from the subject and accepted
direction. Use a small coherent token system and existing components. Purposeful
structure beats repeating generic cards or identical reveal effects. A clear
user-specified style wins over an anti-template preference.

For task-oriented UI, consistency and familiar affordances matter more than
novelty. Distinguish primary actions and semantic states; use readable type,
visible focus and adequate contrast. Keep overlays unclipped and controls
reachable. On phones, recompose navigation and content for the task instead
of shrinking the desktop arrangement.

Choose imagery/3D/media only when it serves the brief. A procedural asset or
pre-rendered illustration can supply character without a live GPU scene.
Preserve a usable default when optional media is unavailable.

## Validate what was built

Inspect real content at relevant viewports. Check hierarchy, spacing, overflow,
contrast, focus and control states. On interactive surfaces, drive each
reachable state (open, closed, hover, focus, error, empty, overlong content)
and check it for overlap and clipping, not only the resting screen. Follow the
UX acceptance reference for actual completion, keyboard and recovery evidence.
Screenshots alone cannot establish gesture quality, screen-reader use or task
completion.

The full upstream package's launcher, hooks, mandatory context files, separate
confirmation lifecycle and categorical visual bans are intentionally excluded.
Accepted requirements and the current Matt phase govern these decisions.
